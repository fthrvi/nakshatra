# Nakshatra node container

This is the default host boundary for a donated Nakshatra node. The container sees one
named state volume and, only when explicitly configured, one `/share` bind mount. It does
not mount the host home, Docker socket, SSH directory, cloud credentials, or WireGuard
configuration. Nakshatra remains inference/compute only: this container never joins a
WireGuard mesh.

The practical protection is simple: Nakshatra code, models, and a compromised process in
the node cannot browse the friend's personal files. Node keys, the test person key,
release prefix, worker builds, and model slices remain in the `nakshatra-node-state`
volume. The optional host share is read-only unless the owner explicitly selects
`--share-rw`.

This is not a boundary against a compromised host. Host root, Docker's root daemon, or the
owner of a rootless Podman account can inspect the volume and the container. A worker also
necessarily sees prompts and activations it serves. Containers reduce host-file exposure;
they do not make inference private from the worker doing it, and they do not defend against
container-runtime or kernel escapes. Bridge networking still permits outbound LAN and Internet
access, including any host service reachable over the bridge; it is not isolation from personal
data exposed over the network. The state volume is writable by the same UID as the node, so a
compromised process can alter its own installed releases and keys. That does not grant access to
unmounted host files, but the volume must not be treated as tamper-proof.

## A friend's setup

Install Docker Desktop/Docker Engine or Podman, copy `nakc` and the adjacent container
directory, then make the wrapper available on `PATH`:

```sh
chmod +x deploy/container/nakc
ln -s "$PWD/deploy/container/nakc" ~/.local/bin/nakc
nakc join "<the complete one-line invite from your friend>"
```

`nakc join` does not evaluate that line in a shell. It accepts only the exact format made
by `nak invite`, downloads `install.py` and `releasekit.py`, checks both SHA-256 fingerprints
from the line, and only then runs `install.py join`. That installer verifies the invite,
pins its release key, verifies the signed release manifest and every payload, and records
the pinned key in the named volume. Hourly updates run the updater unit generated by the
installed signed release; they retain the same key, expiry, manifest, hash, monotonic-version,
health-check, and rollback rules as a normal node.

To donate compute, build the engine and then use the same worker command as a bare node:

```sh
nakc worker build
nakc worker on --model-id MODEL --package-url URL --package-pubkey PUBKEY \
  --pillar-url URL --pillar-spki SHA256 --layers 0-16 --port 50051
```

Finally register the stdio MCP bridge with the host harness. For OpenClaw:

```sh
openclaw mcp add nakshatra --command "nakc mcp"
```

Claude Code and Hermes can use `nakc mcp` as the command in their equivalent stdio MCP
configuration. The wrapper uses `exec <engine> exec -i <container> nak-mcp`, so protocol
stdin/stdout stays direct and supervisor logs remain on the container's log stream.

Normal operation:

```sh
nakc start
nakc status
nakc logs
nakc update
nakc stop
```

## Optional share

No host path is mounted by default. To expose one deliberate directory:

```sh
mkdir -p ~/nakshatra-share
nakc share ~/nakshatra-share                 # /share, read-only
nakc share --share-rw ~/nakshatra-share      # explicit write permission
```

Changing the share recreates only the disposable container. The named state volume and its
keys are retained. Removing the container likewise does not remove the volume; back up or
delete that volume only as a separate, deliberate operation.

## Runtime hardening and ports

`nakc` prefers Podman when available and otherwise uses Docker. Override with
`NAKC_ENGINE=docker` or `NAKC_ENGINE=podman`. Every start uses a non-root UID, drops all
capabilities, enables `no-new-privileges`, uses a read-only root filesystem, supplies only a
bounded `/tmp` tmpfs, uses the normal container network namespace, and applies memory and
PID limits. The gateway binds `0.0.0.0:11599` only inside the container and maps only to host
loopback at `127.0.0.1:11600`. The worker's gRPC port always binds container loopback and is
never published. While the worker is on, its libp2p sidecar is the one deliberate public ingress:
`0.0.0.0:4001` over both TCP and UDP/QUIC by default. Set `NAKC_P2P_PORT` on the first
`nakc worker on` to choose another fixed port. Turning the worker off removes both publications.
Host networking is never used.

Tune resource ceilings without weakening the file boundary:

```sh
NAKC_MEMORY=32g NAKC_PIDS_LIMIT=1024 nakc start
```

The image defaults to CPU. GPU images include development toolchains because `nak worker
build` compiles the release-pinned engine inside the container:

```sh
NAKC_VARIANT=nvidia nakc start   # CUDA image; Docker --gpus or Podman CDI
NAKC_VARIANT=rocm nakc start     # ROCm image; only /dev/kfd and /dev/dri
```

The default build bases are pinned by version tag, not immutable digest, in `nakc` and
`Containerfile`; image construction is outside Nakshatra release signing. Set `NAKC_IMAGE`
to use a prebuilt official image instead of the locally built `nakshatra-node:<variant>`.
NVIDIA requires the NVIDIA container runtime/CDI setup on the host; ROCm requires host
device permissions. Neither mode mounts the host filesystem beyond the optional share.

## Supervisor design

`tini` is PID 1 and forwards signals/reaps adopted children. A standard-library Python
supervisor then asks the signed release's own installer for `write-units --no-systemd`
output and parses the small unit subset it emits (`EnvironmentFile`, `Environment`,
`ExecStartPre`, `ExecStart`, and `Restart`). There is no second copy of service command
lines. Processes restart with capped exponential backoff and receive SIGTERM during a clean
container stop.

The container exposes a narrow `systemctl --user` compatibility shim to the signed installer.
It supports only the operations the installer and `nak` use: reload, enable/disable,
restart, and status queries. That keeps `install.py join/update`, profile hydration, and
`nak worker on/off` on their established signed path without putting systemd or sudo in the
image.
